## v2.3 hotfix — restore dark glass on cale-auto + pakiet-front (2026-05-20 late night)

**Problem.** Oskar caught a perceptual bug on `pakiet-front/front`, `cale-auto/front`, `cale-auto/rear`: the cars looked "vertically stretched" vs `progi` / `reflektory`. Diagnosis: cars were pixel-aligned with `base` (bounding-box identical), but `nano_banana_2` had painted the **glass** (windshield, side windows, rear quarter) crimson along with the body. With the dark-window contrast gone, the G-Class greenhouse merged into the body silhouette → eye reads the whole upper section as one monolithic block → perceived as taller. PPF doesn't go over glass anyway, so the model output was also factually wrong.

**Fix (no Higgsfield regen).** Composite `base`'s dark glass back over the affected packages via ImageMagick. Pixel-perfect because the car geometry already matches.

**Recipe** (front view; rear is identical with the rear PNGs):

```bash
# 1. Build glass mask from base (sips-normalize first per libpng workaround)
cd assets-src/ppf/raw/_normalized

magick base/front.png -colorspace gray -threshold 30% -channel RGB -negate \
  -fill black \
  -floodfill +0+0 "white" -floodfill +2399+0 "white" \
  -floodfill +0+1791 "white" -floodfill +2399+1791 "white" \
  /tmp/ppf-fix/mask_front_v1.png

# 2. Clean: morphological open kills thin chrome trim, large windows survive
magick /tmp/ppf-fix/mask_front_v1.png -morphology Open Disk:10 /tmp/ppf-fix/mask_front_v6.png

# 3. Constrain to greenhouse y-band only (excludes grille top + bumper trim)
magick /tmp/ppf-fix/mask_front_v6.png \
  -fill black -draw "rectangle 0,0 2400,490" -draw "rectangle 0,820 2400,1792" \
  /tmp/ppf-fix/mask_front_v7.png

# 4. Composite: base glass over package body, masked by glass mask
# Syntax: <bottom> <top> <mask> -composite → result = top where mask=white, bottom where mask=black
magick packages/cale-auto/front.png base/front.png /tmp/ppf-fix/mask_front_v7.png \
  -composite /tmp/ppf-fix/cale-auto_front_fixed.png

# 5. cwebp to 2000×1493 q=82 → public/ppf/packages/<slug>/front.webp
cwebp -q 82 -m 6 -mt -resize 2000 1493 \
  /tmp/ppf-fix/cale-auto_front_fixed.png \
  -o public/ppf/packages/cale-auto/front.webp
```

For rear: same recipe with `base/rear.png` + y-band `0,500` and `0,790` (greenhouse on rear 3/4 sits slightly tighter than front).

**Visual verdict.** Live smoke test on `:5180`: G-Brabus silhouette reads correctly across all 4 packages × 2 views. The "stretched" perception is gone. No regen credits spent.

**General rule going forward.** When generating PPF / wrap / coating coverage maps via `nano_banana_2` (or any text-to-image model), the model tends to paint EVERYTHING in the covered zone — including glass. Either (a) add explicit "GLASS MUST STAY DARK — windshield, side windows, rear quarter are not panels" exclusion to the prompt, or (b) use the post-process composite recipe above to surgically restore dark glass from `base`. (b) is cheaper and more reliable.

The model paints a semi-transparent crimson overlay on the covered panels — treating the image like a Photoshop "Solid Color" layer at ~50% opacity. The result reads instantly: "this panel is red = this panel is in the package."
- Also fixed: phase 2 package webps were 1200×896 (default 1k Higgsfield output), but base webps were 2000×1493. v2.1 generates at 2k and `cwebp -resize 2000 1493` normalises everything to a unified dimension.
